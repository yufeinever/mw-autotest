# 邮箱用例153～156的独立基线

参考客户端：v2026.02.01；后续迭代核对实际字段、分类和接口，同步修改共用实现及用例。

这四条使用真实内置邮箱工作台。组件接口与UI一致只能验证回显；收件数量、邮件正文和AI分析准确性仍需独立邮箱事实。没有基线时脚本继续只读检查，完整业务结论保留REVIEW。155仅对基线中明确标记可丢弃、ID及标题同时匹配的待办邮件执行“标记已处理”，不发送邮件、不直接改产品状态文件。

## 提供方式

在启动18888控制台的同一终端，设置 `MW_TEST_MAIL_BASELINE` 为专用测试邮箱基线JSON的绝对路径，然后按原启动方式运行控制台；路径和内容由子任务运行时读取，不提交真实邮件或凭证。已启动进程不会自动继承新环境变量，需待队列空闲后正常重启，保留原数据目录和18888端口。

基线来自专用测试邮箱的实际收件/处理记录，不能复制被测dashboard响应充当独立来源。`observedAt`为本次核对时间，须与执行时北京时间同日；核对期间保持专用测试邮箱不被其他任务改动，跨日重新采集。`summary`为完整邮箱统计，`messages`是本次需要逐条核对的测试邮件，可以是其中一个子集。邮件ID须与客户端同步记录对应。

下面仅是数据结构示例，不是已经投递或处理过的邮件。应替换成当日真实测试记录，不能原样用于证明通过。

```json
{
  "source": "external-test-mailbox",
  "observedAt": "2026-11-01T10:00:00+08:00",
  "summary": {"receivedToday": 3, "pending": 2, "handledThisWeek": 1},
  "summaryFacts": ["项目评审", "预算确认"],
  "messages": [{
    "id": "实际同步的测试邮件ID",
    "title": "测试项目评审确认",
    "receivedAt": "2026-11-01",
    "senderName": "测试发件人",
    "senderEmail": "qa@example.invalid",
    "deadlineAt": "2026-11-01 17:00",
    "deadlineMs": 1793523600000,
    "status": "pending",
    "priority": "high",
    "actionable": true,
    "asap": false,
    "disposable": true,
    "bodyFacts": ["项目评审", "17:00"],
    "aiFacts": ["项目评审", "确认"]
  }]
}
```

`actionable`、`asap`和截止事实来自邮件原文，用于判断通知类低优、当日截止/尽快高优、其余需办理中优。`bodyFacts`和`aiFacts`只列关键事实，不固定模型完整措辞。`disposable=true`表示允许这封测试邮件被不可逆标记已处理；标记后旧基线不再可供相同场景重复使用，应新建独立测试邮件并重新采集。

## 当前差异

- 154：原表要求待办分布，当前圆环及点击采用近7天全部邮件。脚本分别记录口径，保留REVIEW。
- 155：当前待办卡片没有原表要求的AI摘要及独立处理状态字段；不会改写成字段完整通过。
- 156：正文失败回退摘要不能作为正文准确通过；AI分析未终态时保留本轮弹框和资源归属，等待收尾确认，不提前放行。

运行结果、截图和日志仍由统一runner及控制台归档；此文件不是独立执行入口。

## 157～160 扩展输入

仍使用同一份 `MW_TEST_MAIL_BASELINE`，旧153～156基线不要求补新字段。新增字段按专项需要填写，不能由被测接口响应生成独立事实。

- 157：目标 `messages` 中增加 `replyFacts`（原文要求回复覆盖的关键事实）及可选 `replyForbiddenFacts`（不得编造的具体事实）。不要求固定措辞；只生成、编辑、取消草稿，不发送。当前AI起草在详情，写信弹框内的“AI润色”不是起草。
- 158/160：增加 `history={complete:true,fromMs,throughMs,records:[...]}`，每条包含真实 `id,timeMs,title,senderName,senderEmail` 和可选 `handledAt`。时间均为毫秒时间戳；158须覆盖前三周周一至观测时刻，包含更早收到但在此范围处理的邮件；160原规则核对须覆盖近7天，核查当前30天规则时再扩充30天。不得只填写本轮几封测试邮件。统计以 `observedAt` 为核对时点，核对期间专用邮箱保持不变。周统计按北京时间周一，收到和处理分别按各自时间归桶。原表联系人目标仍为7天Top10，安装版30天Top8差异不静默豁免。
- 159：增加 `meetings` 独立原邮件事实：`id,sourceMailId,title,startMs,online:{app,url,meetingNo},disposable`。提醒变更另外要求 `testReminder:true`、标题以 `MW-Autotest-Meeting-` 开头且唯一、会议在执行时30～60分钟后开始，当前默认提前5分钟、尚未领取或触发。依次设置15/30分钟时不应提前到期，最后60分钟自然到期；观察真实右下提醒及至少65秒去重。仅该专用可丢弃提醒在结束后取消，不恢复已触发标记或重新武装用户会议。原链接跳转和关闭提醒UI缺口保留REVIEW，不把复制和收尾API当成原功能通过。
- 160：增加 `send={authorized:true,confirmedAt:"当天ISO时间",name:"专用测试联系人",recipient:"专用测试邮箱"}`，必须精确匹配真实联系人。此字段代表明确允许向该专用收件人真实发送本轮测试邮件，不能配置真实客户/同事或批量联系人。无字段只查空白新信及预填，不发送。

160发信主题和正文随机标记在发送前登记，本地发件箱唯一记录确认前不会重发或假定已停止。另通过 `MW_TEST_MAIL_RECEIPT` 指向独立测试收件箱收据JSON，格式为 `{source:"external-test-mailbox",recipient,subject,body,receivedAt,messageId}`；主题、收件人和正文标记必须匹配本轮且收件时间不早于发送。缺独立收据只证明本机发送记录，实际送达保留REVIEW。收据在发送后由独立邮箱采集，不预制成功记录。

## 161 天气独立观测

运行时 `MW_TEST_WEATHER_BASELINE` 指向独立气象来源JSON，字段为 `source:"independent-weather-observation"`、`provider`、`city`、`latitude`、`longitude`、`observedAt`、`temperature`、`minimum`、`maximum`、`humidity`、`windSpeed`、`windDirection`、`tolerance:{temperature,humidity,windSpeed,windDirection}`。温度摄氏度、湿度百分比、风速km/h、风向度数。观测须在一小时内，provider不能使用被测Open-Meteo作为独立来源，各误差明确且非负。

客户端城市与请求坐标必须对应基线，方向按圆周最小夹角核对。真实forecast仅证明本轮请求与回显，缺独立气象事实不证明天气准确。当前显示风力等级、无手动刷新按钮且每小时自动刷新；本条不改时钟或城市，不将风力等级当数值风速、缓存当实时或加载当自动刷新通过。
