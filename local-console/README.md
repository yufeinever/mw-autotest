# 本机测试控制台

双击 `测试用例与脚本/打开测试控制台.cmd`，或运行 `node local-console/launch.mjs`。默认固定地址为 http://127.0.0.1:18888 ，重复启动复用同目录且支持批次和任务调度的服务；端口冲突报错，不自动换端口。显式设置 `MW_CONSOLE_PORT` 可覆盖默认值。升级后端时待任务结束，再正常关闭旧服务并重新启动，沿用原数据目录；代码改动不会自动迁移已经运行的17868服务，切换前应先关闭旧服务，避免两个服务同时写入同一目录。

1. 在“01 / 执行配置”设置选项、审批和模型；“02 / 脚本列表”仅按序串行执行。选择“勾选用例”可跨页全选、反选或清空，也可切换到互斥的“序号范围 m-n”；切换会清空另一模式。已取消并行及执行下条。点击脚本名只读查看源码，最近执行列直接查看截图报告；报告、Trace和批次以页内预览打开，关闭立即返回原页码、勾选与滚动位置。
2. 前16条用例已内置。其他脚本可点击“添加脚本”，粘贴绝对路径或浏览本机目录。升级自动补充缺少的内置入口，保留原ID、命名和自定义脚本。
3. 点击对应行“执行”。当前页面参数作为不可变快照传给该次运行；保存配置不会修改正在执行的任务。
4. “03 / 执行批次”按每次单条、全部或范围执行汇总，显示范围、开始/结束时间、已结束进度、执行结果及实际断言通过率，默认每页30个批次，支持10/30/50及翻页。点击批次名或“查看批次”进入详情，再查看各用例报告、配置、结果、断言、按发生顺序展开的步骤截图与日志。脚本退出码为0不等于用例通过。
5. 批次详情的“Trace 记录”展示对应会话的消息、工具调用、输入输出、状态、错误和耗时，可下载脱敏 Trace JSON；失败、阻塞、停止记录同样支持。没有会话ID时显示原因，不生成伪造记录。

批次计划及脱敏参数保存在 `runtime-config/test-console/batches`，用例job.json通过batchId关联；提交失败保留整批计划及尚未执行项。重启时未完成提交的批次标记中断，不补跑、不伪报通过。未记录batchId的旧记录集中展示为“历史执行记录”，明确是历史归档，不推断其原批次，不改写旧报告。批次详情地址 `/?batch=批次ID` 可刷新和直接访问，执行中每2秒更新。

控制台固定18888端口，沿用 `runtime-config/test-console/current-store.json` 指向的数据目录。只复用同目录且支持 `taskIsolation=2` 的服务；旧服务需在空闲时关闭后重启，不自动换端口。刷新前端会提示版本不匹配并禁止提交，不能代替服务升级。

前16条独立脚本和中文一键入口也通过同一控制台排队，原 `--check`、`--fill-check`、`--resume` 参数会传给后台脚本。草稿按语义文字、Skill ID、URL与选择登记归属，追加前登记预期内容，失败时只清理签名匹配的本任务草稿。脚本退出后服务端核对关联会话与页面交接；未恢复时后续任务保持QUEUED并显示原因，每5秒复查，恢复后继续。失败任务的关联会话可在确认归属后停止并复查空闲，原报告结果不变；用户草稿或未知弹窗不会自动删除。历史旧版记录不自动重跑或恢复。

补丁审批接口出现已识别的JSON序列化400时，产品用例仍记录BLOCKED。收尾先核对Session所属引擎与目录，只停止该会话，再从独立运行状态接口确认空闲；不依赖已经损坏的审批列表。若客户端仍显示这条已停止会话的审批卡片，确认没有用户草稿或弹窗后，点击“新建任务”退出残留页面，不点击旧审批。普通400、归属不明和未知弹窗仍暂停交接。报告单独显示收尾状态，不把恢复成功算成用例通过。

发送前登记的专家/团队选择在Session创建后继续保留为归属证据。模型已完成且页面仍属于本条会话时，如果选择与登记完全一致、输入框为空且无弹窗，可通过“新建任务”退出残留选择。用户改变选择或写入草稿时保持暂停，不擅自清理。旧记录缺少该归属证据时不猜测。

脚本列表为紧凑表格，默认每页5条，可选5/10/20/50条并翻页。悬停脚本名查看完整路径；新增脚本后跳到其所在页。序号按全列表顺序连续编号，不随分页重新计数，移除脚本后以当前显示序号为准。

“全部执行”覆盖所有分页；输入执行序号 `m-n` 后点“执行范围”，包含m、n两端，例如 `3-8` 执行第3至第8条。批量固定使用点击时的参数和执行策略，先按序登记队列，入队不等于脚本已经启动。文件缺失或未接入参数时整批不提交；中途失败显示已入队数量，不自动重试。具体结论在执行批次查看。

“全部执行”旁的红色“强制停止全部”会取消本页面后续提交，先取消当前控制台的全部排队任务，再停止执行中的脚本和未确认结束的关联会话。停止过程保留日志、截图及历史结果；部分失败会显示具体任务并支持重试。无任务时按钮禁用，停止中显示“正在停止…”。刷新页面即可使用，不需要重启服务或客户端。

串行：上一条结束后再启动下一条。任务并行：逐条准备和提交，核对Session及完整输入后才准备下一条；模型处理阶段可以重叠，按配置限制同时在执行的任务数。提交、弹窗、审批和截图轮流使用同一客户端页面，模型等待使用本任务捕获的引擎及目录接口，不争抢页面、不反复切换会话轮询。没有接入分阶段调度的自定义脚本依次执行。已有会话但结束未确认时暂停后续提交，核对并停止该会话后再继续。

前16条脚本统一保存 `trace.json`，在最终执行结果落盘前追加 Skill 实际调用断言，计入断言通过率。规则 `skills-invocation-v1`：本会话或有可证父子关系的子会话中，目标 `skill` 工具的精确ID、成功完成状态、返回的Skill内容身份和元数据必须一致；同一目标Skill的任一次调用失败也不判通过。仅在提示词中提及、界面勾选或模型声称调用不算证据。未配置Skill预期的专家/团队用例只展示Trace，不生成“Skill通过”断言。

历史报告不改写，Trace页会另行核验已有日志；旧快照未采集子会话时明确说明。新运行保存关联子会话，核对 parentID 和消息归属，并记录采集超时、数量上限及接口错误。调用证据仅证明Skill成功加载，不能代替结果与产物断言。

Trace入口兼容当前已运行的17865服务，刷新页面即可使用。前端入口为 `/?trace=运行ID`，优先读取本次落盘的 `trace.json`，其次读取Session快照，最后回读引擎。前端源码在 `app-source.js`，修改后运行 `npm run build:console` 生成 `app.js`。`trace-data.mjs` 和 `trace.mjs` 同时用于浏览器与服务端，避免两套Skill判定规则。

每次运行有独立配置快照、Session和证据目录；批次详情显示排队、提交、等待模型、处理交互和核验结果等阶段。排队任务可取消，尚未启动时没有PID与开始时间。服务重启后队列标记中断，不自动重跑。

“执行”后面的“强制停止”会结束本次脚本进程树，并在有会话 ID 时请求停止该会话；不会退出 MobileWork 客户端。日志和已有截图保留，记录结束时间，结果显示红色“已强制停止”。脚本超时阻塞后仍可停止对应会话；会话停止未确认时页面会明确提示。尚未写入文件的断言不会补造为通过。

选项和审批弹窗每次出现后均等待 1 秒，再执行本次配置的操作；选择第一项时，每次问题均选择第一项。后续弹窗继续按同一配置处理，直到任务结束或超时。

新版提问卡片支持连续多题：点击编号选项会自动切换问题或提交，脚本检查本题控件，避免把“发送”点到下一道题上。没有“跳过”按钮或初始“发送”被禁用时也能识别。自定义回答填写输入框后发送。首条和第二条用例共用 `scripts/mobilework-run-policy.mjs`；回归命令为 `node --test scripts/mobilework-run-policy.test.mjs`。

每条用例在空白新任务输入框核对并恢复“默认权限”，防止继承上一条的完全访问设置；随后按本次配置处理审批弹窗，不修改其他会话的权限。自定义回答会用于每次提问；当界面没有对应选项或输入框，脚本会保留现场并报告阻塞。模型切换在新任务发送前核对。调度内按所属Session切换页面；发现调度外切换或用户草稿时停止界面操作，保留现场。

第3～16条共用 `scripts/client-case-runner.mjs`，各自入口为 `scripts/run-client-case003.mjs` 至 `scripts/run-client-case016.mjs`。素材直接内嵌；报告中的“真实产物”可下载本次生成的代码、归档、PPTX、HTML、SVG等文件。HTML/SVG以附件下载，不在控制台同源执行。完整映射、断言范围和验证状态见 `测试用例与脚本/前16条用例脚本清单.md`。

2026-10-18的新增14条入口已加入当前17865服务；产物下载界面等服务端代码需要正常重启本地控制台后生效。本次自动重载操作被审批策略拒绝，未停止旧服务；请在无脚本执行时关闭原控制台服务窗口，再双击打开入口。无需重启MobileWork客户端。

第3～16条支持 `--check`（只读环境预检）、`--fill-check`（真实场景和素材核对后清理本次草稿，不发送）以及默认完整执行。检查结果 `CHECKED` 不等于用例 `PASS`。文本类用例可用 `--resume=ses_ID` 续跑当前且包含本用例完整材料的会话；文件类需新建运行，避免引用历史产物。

## 新脚本接入

支持 `.mjs/.js/.cjs/.py/.ps1/.cmd/.bat`。脚本必须读取环境变量 `MW_TEST_CONFIG_JSON`（字符串 JSON），并实际落实这些参数。页面通过源码标记检测接入，不保证任意外部脚本实现正确，接入后仍需验证。

```json
{"version":1,"question":"first","customText":"","approval":"once","model":"gpt-6.1-sol","cdpPort":9223}
```

- question：first / second / custom。
- executionStrategy：serial（默认）/ parallel；maxParallel：1～16，默认3。两者保存到批次及每次运行的参数快照。
- approval：reject / once / session / full。
- model：空字符串沿用当前；其他值为客户端模型名称。
- provider：可填写新模型 URL、Key、模型命中、多模态及输入/输出模型长度。脚本通过 `MW_MODEL_CONFIG_JSON` 读取；Key 只作为运行时环境变量传递，不写入报告截图。
- Node 脚本可复用 `scripts/mobilework-run-policy.mjs` 的 `readRunConfig`、`selectModel`、`handleConfiguredDialog`。其他语言读取环境变量后自行实现界面控制；批处理包装器需保留环境变量并明确声明 `MW_TEST_CONFIG_JSON` 接入。
- 工作目录为本项目根目录。额外参数、交互式终端输入暂不支持；Python、PowerShell 需要本机相应运行环境。
- 建议退出码：0 正常结束、1 失败、2 阻塞。输出独立行 `报告：绝对路径`，同目录放 `执行结果.json`，字段 `result` 为 PASS/FAIL/BLOCKED 等；可用 `evidence:[{step,screenshot}]` 提供截图链接。

设置与控制台记录在 `runtime-config/test-console`；首条用例报告仍在 `runs`。目录采用 `MMdd-HHmm-日程管理-第01次`，截图采用 `MMdd-HHmm-序号-中文步骤名.png`。历史目录不改名。

录像页提供“打开所在文件夹”和实际本地路径，方便手动清理MP4。v0.0.12起新录像只存于控制台数据目录的 `recordings/运行ID/执行录像.mp4`，网页报告和播放器共用，不再复制到jobs或runs；删除该MP4可释放空间，报告、日志和业务结果保留。历史版本的jobs源录像、runs报告副本继续可读；页面列出仍存在的历史副本，清理时需分别删除两处MP4，保留目录内其他运行资料。截图只有runs原图一份，网页引用原文件。新文件夹接口需在空闲时重启控制台加载，无需重启MobileWork。

验证：`node --test local-console/console.test.mjs`。使用隔离临时目录和模拟页面，不向 MobileWork 发送任务。

执行调度验证覆盖串行顺序、旧并行参数兼容、队列取消、阻塞暂停、重启不补跑及Session归属。开发后按最多5例约定选取定向测试，不默认运行整套历史文件；模拟通过不代表前16条产品实机全部通过。此次易用性定向回归入口：`node --test local-console/usability.test.mjs`（4项）。

Trace回归：`node --test --test-concurrency=1 local-console/trace.test.mjs local-console/session-log.test.mjs`。与前16条框架、交互和会议内容回归合计33项通过。`node scripts/verify-mobilework-trace.mjs` 对已有001、002、003、006会话作只读调用审计，并用Playwright实测当前17865页面的入口、真实工具详情展开和JSON下载，不重算历史通过率，不代表其他12条用例完成实机执行。
